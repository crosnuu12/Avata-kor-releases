# Avata 1.1.14 / 58.17.20

토큰을 새로 발급받은 뒤에도 인증 조회가 거절될 때 재발급 요청이 계속 반복되는 복구 경로를 보완합니다. 최초 토큰 거부의 서버 측 원인은 아직 확정되지 않았으며, 이번 변경은 재현된 재시도·캐시 결함의 수정과 원인 구분용 진단 추가입니다.

## 확인된 문제와 변경

- 기존에는 GET 1건 안에서만 재발급 횟수를 제한했습니다. 여러 조회 주기를 실행하면 매번 발급 2회·조회 2회가 반복됐습니다. 새 버전은 일시 만료의 즉시 재발급 1회는 유지하고, 복구에 실패하면 30·60·120·300초 간격으로 제한합니다. 인증된 조회가 성공해야 제한을 초기화합니다.
- 자산 조회 작업자는 주기마다 다시 만들어집니다. 거절된 토큰이 빈 값으로 바뀌었을 때도 예전 저장 파일은 남아 다음 작업자가 이를 재사용할 수 있었습니다. 거절 상태와 재시도 시각을 함께 보존해 이 반복을 막습니다.
- 명시적인 자격증명 오류 `EGW00103`을 HTTP 401보다 우선하여 분류합니다. 잘못된 키를 단순 만료로 오인하지 않습니다.
- 토큰 발급 성공·실패, 갱신 후 거부, 직전 거부 토큰과 같은 값인지 여부, 수명·경과 시간·재시도 시각·HTTP/API 코드만 진단합니다. 토큰·키·응답 원문·토큰 해시는 기록하거나 전송하지 않습니다.

## 자동매매 경계

인증 조회 실패 중에는 신규 주문을 보내지 않습니다. 이미 시작한 실주문 의도는 기존 범위 안에서 유지하되, 복구 후 새 계좌 대조 두 번을 거쳐야 합니다. 실주문이 꺼져 있으면 자동으로 켜지지 않습니다. 정지 요청과 주문 거절 검토는 인증 복구로 해제하지 않으며, 주문 POST를 인증 GET처럼 재전송하지 않습니다.

## 근거와 확인 범위

합성 재현에서 기존 코드의 3회 실패 주기는 토큰 발급/GET 누적이 `2/2 → 4/4 → 6/6`으로 늘었습니다. `EGW00103 + HTTP 401` 오분류도 별도로 재현했습니다. 운영 인증정보나 실제 주문을 테스트에 사용하지 않습니다.

메리츠 공식 안내는 응답의 `expires_in`으로 토큰을 재사용하고 `EGW00123`·`EGW00121`이면 재발급하도록 설명합니다. 새 발급이 다른 토큰을 폐기한다는 가정으로 동작을 바꾸지 않습니다. [공식 인증 안내](https://openapi.imeritz.com/howto-use)

Windows 검증·공개 배포 결과는 [STATUS.md](STATUS.md)에 기록합니다. 배포 완료와 실제 PC 적용·인증 복구 확인은 별개입니다.
