# Avata 1.1.13 / 58.17.19

## 확인된 문제와 원인

작업자 오류로 실전 상태가 `REVIEW`가 된 뒤 업데이트를 누르면, 정상 계좌 조회가 재개되고 미체결·불확실 주문이 0건이며 대조 확인이 2회 완료되어도 업데이트가 보류될 수 있었습니다.

- 기존 STOP은 `REVIEW`에서 상태를 바꾸지 않았고, 정지 완료 처리는 `STOPPING`에만 있었습니다. 따라서 관리자 안전 조건에 도달하는 경로가 없었습니다.
- 전략 입력을 계좌 조회보다 먼저 검사하여 입력이 만료되면 정지를 위한 증권사 대조까지 실행하지 못했습니다.
- 일시정지·트레이 종료 대기 후 업데이트를 요청해도 이전 종료 의도가 남아, 대조 완료 직후 조회가 다시 멈추거나 창이 닫힐 수 있었습니다.
- 업데이트 화면은 여러 차단 원인을 모두 `주문 정리 후 업데이트`로 표시했습니다. 과거의 확정 거절 주문 문제와 이번 상태 전이 문제가 같은 증상처럼 보였습니다.

실제 로그의 정상 조회·대조 완료와 `DEFER_REVIEW` 조합을 확인하고, 합성 작업자 예외 → 실제 STOP 명령 → 반복 정상 조회 경로에서 같은 막힘을 재현했습니다. 개인 로그와 계좌 자료는 이 저장소에 포함하지 않습니다.

## 수정

- 명시적인 정지 요청에 별도 대조 경로를 사용합니다. 기존 계좌·전략 기준 원장을 검증하고 새로운 증권사 조회와 체결·원장을 대조하며, 전략 입력 만료가 종료 확인을 막지 않게 합니다.
- 정지 요청 이후 서로 다른 새 조회 두 번에서 미체결·미확인 접수·불확실 주문이 없고 계좌가 일치해야 실주문 비활성 상태로 종료합니다. 기존 REVIEW에서는 주문을 전송하거나 취소하지 않습니다.
- 일반 운용 중 STOP의 검증된 AT 잔량 취소 절차는 유지합니다. 신규 주문, 자동 승인, 거절 이력 삭제나 복구 확인 생략은 허용하지 않습니다.
- 저장에 성공한 업데이트 요청은 이전 일시정지·트레이 종료 대기를 해제해 전환에 필요한 조회를 유지합니다. 일반 일시정지·트레이 종료 대기도 새 계좌 대조가 완료된 뒤에만 진행합니다.
- 입력 만료·계좌 대조·주문 확인·작업자 오류·복구 작업 등 실제 업데이트 대기 이유를 표시합니다. 요청 만료 시에는 만료 시점 이후의 호스트 응답을 확인한 뒤 재시도를 허용하여 전환 중 경합을 방지합니다.
- 정상적인 정지 대조 대기는 장애로 알리거나 복구 완료로 앞서 알리지 않습니다. REVIEW·불확실 주문 알림은 유지합니다.
- 입력 읽기 진단의 안전한 사유를 원격 진단에 포함합니다. 계좌·인증정보·원문 예외·전체 경로는 제외합니다.

## 검증과 적용 범위

합성 테스트로 원래의 실패 경로와 정지 후 두 번의 새 대조, 만료된 입력, 불확실 주문·미체결·계좌 불일치·오래된 조회 차단을 검증합니다. 최종 Windows PowerShell 5.1 검사와 배포 결과는 [STATUS.md](STATUS.md)에 기록합니다. 실제 계좌·실주문은 테스트에 사용하지 않습니다.

이번 수정은 정지·업데이트가 끝나지 않는 원인을 대상으로 합니다. 이전 버전에서 예외 정보가 사라진 최초 `WORKER_FAILED`의 정확한 원인까지 밝혀졌다는 뜻은 아닙니다. 입력 갱신과 시트 표시 실패의 재시도 간격 차이는 별도 개선 대상으로 남깁니다.

이미 구버전 프로세스가 이 상태에 막혀 있다면 새 코드가 그 프로세스에 자동 주입되지는 않습니다. 정상 종료 후 재실행으로 서명된 새 버전을 적용해야 할 수 있습니다. 설치·정상 동작은 새 버전의 실제 진단으로 별도 확인합니다. 설치된 호스트와 신뢰 키는 변경하지 않습니다.
