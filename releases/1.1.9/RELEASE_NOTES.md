# Avata 1.1.9 / 58.17.15

확정된 과거 주문 거부 때문에 사용자가 실주문 시작을 다시 눌러도 즉시 중지되는 문제를 수정합니다.

- 사용자가 화면에서 `실주문 시작`을 직접 누르면, 주문번호가 있고 체결·잔량이 모두 0인 확정 거부 기록만 해당 실행 세션에서 확인한 것으로 처리합니다. 원장 기록은 그대로 보존합니다.
- 새 계좌 대조 2회와 기존 입력·자금·위험 검사를 다시 통과해야 합니다. 장외에는 개장 대기를 유지하고, 장중에는 주문 조건이 충족되어야 진행합니다.
- 새 주문 거부가 발생하면 다시 중지합니다. 자동 시작과 텔레그램 시작은 과거 거부를 자동 승인하지 않습니다.
- 조회 불명, 주문번호 누락, 부분 체결, 원장 불일치 및 미해결 주문은 계속 차단합니다.
- 정상 접수된 미체결 주문의 추적과 정지 후 잔량 취소를 유지합니다.

이 변경은 거부 원인이 사이드카였음을 판정하지 않습니다. 과거 거부의 실제 원인은 증권사 응답 코드와 시각으로 확인해야 합니다.

## 적용

기존 아바타의 업데이트 버튼으로 적용합니다. 버전 `1.1.9` 확인 후 화면의 `실주문 시작`을 직접 눌러 현재 상태를 확인하세요. 확정 거부 이외의 차단 사유는 자동 해제하지 않습니다.

## 검증

실계좌·실주문 없이 합성 데이터로 Windows PowerShell 5.1 회귀검증, 장외→날짜 전환→개장 재개, 새 거부 재차단, 정상 주문 추적·정지 취소, 트레이·시작 및 서명된 업데이트를 검사합니다. 최종 공개 결과는 GitHub Actions와 `STATUS.md`를 확인하세요.
