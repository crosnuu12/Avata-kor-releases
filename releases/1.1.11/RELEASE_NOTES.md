# Avata 1.1.11 / 58.17.17

빈 진단 보관함에서 반복되던 `DIAG_ARCHIVE_STATE_RECOVERY`를 수정했습니다. Google Sheets가 빈 범위의 `values`를 생략하거나 null로 반환해도 보관을 시작하고, 기존 PC의 대기 기록은 삭제하지 않고 전송합니다.

- 실시간 진단 요약을 먼저 갱신하고, 아카이브는 실행당 최대 100건씩 전송합니다. 오래 밀린 기록 때문에 최신 상태 전송이 기다리지 않도록 했습니다.
- 원격 기록 형식·순서 검증과 고정 행 재전송을 유지합니다. 손상된 보관함은 무조건 초기화하지 않으며, 응답을 받지 못한 전송도 같은 위치에 재시도합니다.
- 대기 전송은 `DIAG_ARCHIVE_CATCHING_UP`으로 구분합니다. 완료 기준은 `ArchiveCode=OK` 및 `ArchivePending=0`입니다.
- 복구 단계·대기·완료·확인 건수를 허용된 진단 항목에 추가했습니다. 인증정보나 거래 원장은 전송하지 않습니다.
- 읽기 TIMEOUT 후 실주문 허용 의도 유지, 재대조 전 신규 주문 차단, 복구 후 대기 재개를 합성 테스트로 검증합니다. 불확실한 주문 제출 결과는 별도 대조 대상으로 유지합니다.

거래 승인, 매수·매도 전략, 주문 수량·가격 및 주문 재시도 정책은 변경하지 않습니다. 실계좌·실주문·실제 Telegram 메시지로 테스트하지 않습니다.

## 적용과 확인

아바타 업데이트 버튼으로 기존 정지·주문 확인 절차를 거쳐 적용합니다. 새 버전 공개와 PC 설치는 별개입니다. 적용 후 관리 상태와 조회 상태를 확인하고, 필요한 경우 사용자가 실주문 시작을 다시 눌러 장외 대기 상태를 확인합니다. 거부 주문 확인 이력이 유효하면 매번 복구 절차를 반복할 필요가 없으며, 새 거부 또는 불확실 주문이 있으면 기존 확인 절차를 따릅니다.

대기 로그는 다음 수집 주기마다 나누어 전송되므로 설치 직후 0건이 아닐 수 있습니다. 대기 건수 감소와 마지막 아카이브 성공 시각을 확인합니다. 업데이트 때문에 기존 큐나 로그를 삭제하지 않습니다.

검증 및 공개 배포 결과는 [STATUS.md](STATUS.md)에 기록합니다.
